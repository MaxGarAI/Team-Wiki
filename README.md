# Система знаний команды (Память команды: поиск по своим данным + память)

Интеллектуальная система корпоративной базы знаний, предназначенная для быстрого и точного поиска ответов по внутренним материалам команды. Система строго следует принципу доказуемости: каждый ответ сопровождается точными цитатами-источниками, а при нехватке данных система честно возвращает статус `needs_review=true` и фиксирует причину в аудите.

---

## 🎯 Ценность продукта
- **Экономия времени**: Мгновенные ответы на повторяющиеся вопросы новичков, операторов поддержки и разработчиков.
- **Единая точка правды**: Вся актуальная информация собрана в структурированную базу данных с историей обращений.
- **Доказуемость и безопасность**: Никаких выдуманных фактов (галлюцинаций) — каждый ответ подкреплен цитатами из оригинальных документов.
- **Честный аудит**: Если данных недостаточно или уверенность низкая, система выставляет флаг `needs_review=true` и сохраняет причину в историю и журнал аудита.

---

## 👥 Сценарии пользователей

1. **Сценарий 1: Загрузка документов**
   - Пользователь загружает внутренний регламент, инструкцию или шаблон через веб-панель или API (`POST /kb/documents`).
   - Документ автоматически разбивается на абзацы (сниппеты), индексируется и появляется в витрине документов.

2. **Сценарий 2: Ответ с подтверждением источниками**
   - Пользователь задаёт вопрос (например, *«Какой SLA установлен для ответа на код-ревью?»*).
   - Система находит релевантный фрагмент, формирует ответ, прикрепляет точные цитаты (`sources`) и устанавливает `needs_review=false`.

3. **Сценарий 3: Нехватка данных и ручная проверка**
   - Пользователь задаёт вопрос, информации по которому нет в базе (например, *«По какому курсу принимается криптовалюта?»*).
   - Система возвращает честный ответ в духе *«Данных недостаточно для ответа на этот вопрос»*, возвращает пустой массив источников (`sources: []`), устанавливает `needs_review=true` и записывает причину в `qa_runs.error` и `audit_runs.error`.

---

## 🛠️ Архитектура и база данных (SQLite)

Система построена на базе **FastAPI** и **SQLite** (`knowledge_base.db`):

- `documents`: Хранит оригинальные документы (`id`, `created_at`, `title`, `text`).
- `snippets`: Фрагменты документов, нарезанные по абзацам (`id`, `created_at`, `document_id`, `snippet_text`).
- `qa_runs`: История всех заданных вопросов (`id`, `created_at`, `question`, `answer`, `sources_json`, `needs_review`, `error`).
- `audit_runs`: Полный аудит вызовов команд сервиса (`id`, `created_at`, `action`, `input`, `output`, `status`, `error`, `duration_ms`).

**Требование к инвариантам:**
- `sources_json` содержит массив `[{ "document_id": "...", "quote": "..." }]`.
- Если `sources_json` пустой, то `needs_review` **обязательно** равен `true`.
- Если `needs_review=false`, массив `sources` **никогда не пустой**.

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Заполнение базы данных тестовыми документами
```bash
python seed_db.py
```

### 3. Запуск веб-сервиса
```bash
python -m uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```
После запуска откройте в браузере: **http://127.0.0.1:8000**

## 💻 Мини-примеры запросов (cURL)

### 1) Добавить документ (`POST /kb/documents`)
```bash
curl -X POST "http://127.0.0.1:8000/kb/documents" \
     -H "Content-Type: application/json" \
     -d '{
       "title": "Правила проведения 1-on-1 встреч",
       "text": "Встречи 1-on-1 проводятся раз в две недели между сотрудником и тимлидом.\n\nДлительность встречи составляет от 45 до 60 минут. Основная цель — обсуждение развития, обратная связь и устранение сложностей."
     }'
```
*Пример ответа:*
```json
{
  "status": "ok",
  "document_id": "c71be399-4705-4c6e-8260-2ff580139b4f"
}
```

### 2) Удалить документ (`DELETE /kb/documents/{document_id}`)
```bash
curl -X DELETE "http://127.0.0.1:8000/kb/documents/c71be399-4705-4c6e-8260-2ff580139b4f"
```
*Пример ответа:*
```json
{
  "status": "ok",
  "deleted_document_id": "c71be399-4705-4c6e-8260-2ff580139b4f"
}
```

### 3) Задать вопрос системе (`POST /kb/ask`)
```bash
curl -X POST "http://127.0.0.1:8000/kb/ask" \
     -H "Content-Type: application/json" \
     -d '{
       "question": "Какой SLA установлен для ответа на код-ревью?"
     }'
```
*Пример ответа:*
```json
{
  "answer": "SLA для первичного ответа на код-ревью составляет 4 рабочих часа с момента назначения ревьюера. Для каждого Pull Request требуется минимум 2 аппрува от старших инженеров или тимлида.",
  "sources": [
    {
      "document_id": "f51b9247-ba6e-41a6-8964-b0492cb9e1e1",
      "quote": "SLA для первичного ответа на код-ревью составляет 4 рабочих часа с момента назначения ревьюера."
    }
  ],
  "needs_review": false
}
```

### 4) ИИ-ответ с источниками (`POST /ai/answer_with_sources`)
```bash
curl -X POST "http://127.0.0.1:8000/ai/answer_with_sources" \
     -H "Content-Type: application/json" \
     -d '{
       "question": "Что означает термин RPO?",
       "context": "RPO (Recovery Point Objective) — целевая точка восстановления, максимальный допустимый период времени потери данных. В нашей компании норматив RPO составляет 6 часов."
     }'
```
*Пример ответа (строгий JSON):*
```json
{
  "answer": "RPO (Recovery Point Objective) — целевая точка восстановления, максимальный допустимый период времени потери данных. В нашей компании норматив RPO составляет 6 часов.",
  "sources": [
    {
      "quote": "RPO (Recovery Point Objective) — целевая точка восстановления, максимальный допустимый период времени потери данных. В нашей компании норматив RPO составляет 6 часов."
    }
  ],
  "confidence": "high",
  "needs_review": false
}
```

Тестовые наборы расположены в каталоге `tests_data/`:
- `tests_data/kb_documents.jsonl` — 5 подробных документов (по 20–50 строк каждый).

## 🔬 Запуск автоматических тестов

Для запуска всех тестов выполните:
```bash
python run_tests.py
```
или
```bash
python -m unittest discover tests
```

Тесты проверяют:
- Валидацию полей при добавлении документов (422 при пустых или некорректных значениях).
- Загрузку 5 документов и нарезку на абзацы.
- Прогон всех 10 контрольных вопросов и 100% совпадение `needs_review` с `expected_needs_review`.
- Строгость контрактов (непустые цитаты при `needs_review=false`, пустые при `needs_review=true`).
- Работу метода `POST /ai/answer_with_sources` со строгой JSON-схемой.
- Фильтрацию и структуру истории запросов и аудита.

## 🖥️ Веб-панель (3 раздела)

Веб-интерфейс доступен по адресу главной страницы сервиса (`http://127.0.0.1:8000`):
1. **Раздел «📁 Документы»**: Таблица добавленных документов, форма загрузки новых материалов и кнопка «Открыть документ» для просмотра текста.
2. **Раздел «💬 Вопросы»**: Интерактивная строка поиска с быстрыми кнопками-примерами, генерация ответа, цветной бейдж статуса проверки и кликабельные карточки цитат со ссылкой на документ.
3. **Раздел «📜 История»**: Список последних 100 запросов, фильтр «Только требующие проверки» и модальное окно подробной карточки запроса с указанием причины ручной проверки.
